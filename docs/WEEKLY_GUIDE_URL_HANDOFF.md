# 攻略网页地址更新：App 接口交接

2026-11-08。本文仅定义 Horizon Link App 的读取契约和验收要求，供独立网站项目实现配置与发布；不包含网站项目的实现或运维日志。

## 最小改动

在现有 `weekly.json` **根对象**增加可选字段 `guideUrl`，与 `schemaVersion`、`revision`、`periods` 同级。继续使用 schemaVersion 1、同一份文件及同一内容入口；不用新增接口，也不需要手机登录网站后台。

```json
{
  "schemaVersion": 1,
  "revision": 100,
  "guideUrl": "https://api.xiaoheihe.cn/v3/bbs/app/api/web/share?link_id=YOUR_POST_ID",
  "periods": []
}
```

这只是格式示例，**不能直接覆盖线上文件**。发布时保留真实活动 `periods`，将 URL 换成已核对的小黑盒网页，revision 必须大于实际线上最新值；100 不是约定版本或最低修订。

网站需提供一个“攻略网页地址”输入项、预览/校验及发布操作。后端在保存/发布活动时保留此字段，修改地址也须递增同一个 revision；活动发布不能无意丢掉地址，地址发布不能清空活动。沿用原后端的管理员鉴权和服务器到 COS 写入路径，App 不接收管理员凭据或云密钥。

## 字段校验及回退

| 值 | App 行为 |
| --- | --- |
| 缺少 `guideUrl` 或为 JSON `null` | 使用安装包内置攻略地址，旧内容完全兼容；也用于后台“恢复内置地址” |
| 合法字符串 | 使用这份成功加载快照中的地址 |
| 空字符串、其他类型或非法 URL | 整份更新失败，保留上一份成功快照和独立缓存，地址与活动均不被替换 |

合法地址规则必须同时满足：

- 最长 4096 个 UTF-16 code unit（即 JavaScript `string.length` / Dart `String.length`）；不允许空白、ASCII 控制字符和 DEL，不自动 trim。
- 绝对 HTTPS URL；主机名忽略大小写，必须为 `xiaoheihe.cn` 或以 `.xiaoheihe.cn` 结尾的真实子域名。`api.xiaoheihe.cn` 和 `www.xiaoheihe.cn` 可用；`xiaoheihe.cn.evil.test`、`evilxiaoheihe.cn` 不可用。
- 无用户名/密码，端口仅默认 443 或显式 443，不允许 fragment（包括空的 `#`）。
- 保留路径和完整 query；不要删除分享参数、重新排序/解码/重编码 URL。后台预览应使用实际链接，不伪造文章存在或访问授权。

精确行为以 `parseWeeklyGuideUrl`（`flutter_app/lib/core/web_navigation.dart`）和 `flutter_app/test/weekly_guide_url_test.dart` 为依据。后台应同样校验，但 App 会独立复核。

此字段是**整个内容快照的全局攻略入口**，不绑定某个 period，也不自动随某周过期或切回内置地址。可预先发布活动周期，但不能借此预排多个攻略 URL。需要切换时发布新 revision；恢复旧文章也必须用更高 revision 发布旧 URL。回退到内置地址请显式写 `null`。

## 更新、缓存和页面行为

- 复用原每周服务：同意隐私告知后初始化，先读独立缓存；启动、进入地图/攻略及返回前台触发检查，距上次成功检查不足 6 小时跳过，攻略刷新按钮强制检查。
- 没有额外轮询、推送或新请求。网络失败、超时、非法内容、降修订或同修订变更都会保留上一次成功状态。
- 更新活动和地址必须作为同一份完整 JSON 原子发布。同修订不得改变字节；字段/排版变化也发布新 revision。
- 攻略主按钮和“网页攻略”来源地址同时随 AppController 更新。地址仍不允许手机用户本地编辑。
- 已打开的阅读器保持当前页面；下次从攻略主按钮进入使用最新地址。小黑盒 HTTPS 内部导航继续在 WebView，跨站 HTTPS 经确认后系统浏览器打开；HTTP/危险 scheme 保持阻止。
- 地址不写入设置/驾驶记录，也不改变 version 2 备份格式。离线重启可从原周缓存恢复地址；无有效缓存时用内置地址。

## 发布兼容和注意事项

- 仍上传原 COS `weekly/weekly.json`，公开读取端点直接返回 UTF-8 JSON / HTTP 200，`Cache-Control: no-cache`，整体上限 1 MiB，不跳转登录页或 COS 地址。
- 当前实际读取地址由 App 构建参数 `WEEKLY_CONTENT_URL` 和本工程 `config/weekly-content.json` 决定。本轮没有切换网关地址：不能只把文件发布到另一个域名，就假设现有安装包会自动改读新域名。
- 先更新一次安装包，加入此字段的解析及页面能力；之后只改攻略链接无需重装。旧版 App 忽略未知字段，继续用其内置地址。
- 原本地发布工具没有新增 URL 校验。网站发布前需按本协议校验字段。
- 本轮不安装/使用 Hallmark、不修改网站工程、不部署网页、不上传真实内容。独立网站项目的界面、账号和发布实现记录保存在其自己的项目中。

## 联调验收

1. 用隔离测试数据发布 URL A + revision N，App 同时显示并打开 A；query 参数保持一致。
2. 只改 URL B、递增 revision，手动刷新后主入口与来源地址都变成 B，活动和原设置/驾驶记录保持。
3. 断网、重启验证缓存 B；新周期开始/活动过期不自动更改 B。
4. 非小黑盒 URL、HTTP、凭据、非法端口/fragment、空值字符串等发布校验失败；即使绕过后台，App 仍拒收整份内容并保留 B。
5. 同修订改 URL、旧修订回滚均失败；更高修订写 `null` 后恢复内置链接。
6. 中英文、深浅主题和窄屏可读；跨站导航仍有确认，旧 JSON 无新字段可正常使用。

真实网站后台发布 → COS/网关 → 同安装包更新的端到端测试需待另一项目完成；不得将本机单元测试当作已上线。测试内容不能覆盖真实活动。
