# Horizon Link 问题反馈

Android 和 iOS 的入口为「设置 → 关于与帮助 → 问题反馈」。只有点击「发送反馈」才提交。失败时保留当前页面中的输入，重试同一份内容沿用原编号。收到有效回执后显示可复制的编号。离开页面时丢弃草稿。反馈不写入设置、驾驶记录或备份。Web 预览不显示此入口。

## App 对接协议

App 使用 `POST https://ninaaa.cloud/api/horizon-link/feedback`，请求和响应均为 UTF‑8 JSON。接口不要求登录或 App 密钥，不跳转。客户端在 12 秒后结束等待，最多接收 2 KiB 回执。

| 请求字段 | 规则 |
| --- | --- |
| `requestId` | 必填，32 位小写十六进制。由 App 对每份提交随机生成。 |
| `message` | 必填，去掉首尾空白后 1–2,000 个 Unicode 码点，可包含换行。JavaScript 可用 `[...message].length` 核对。 |
| `platform` | 必填，`android` 或 `ios`。 |
| `appVersion` | 可选，例如 `0.3.2+5`。版本不可读取时省略。格式 `^\d{1,9}\.\d{1,9}\.\d{1,9}\+\d{1,10}$`。 |

首次持久化后返回 `201`。相同编号及相同内容重试返回 `200`，复用原记录。两者都返回 `Content-Type: application/json`，响应形如 `{"id":"5d0e6f8bc839445fa2455881f1fce7a4"}`，`id` 必须等于请求的 `requestId`。相同编号而内容不同返回 `409`。超过服务端频率限制返回 `429`。无效请求用 `400`，请求过大用 `413`，内容类型错误用 `415`。App 对 `429` 单独提示，其他错误保留输入并提示稍后重试。

## 可直接复制到个人网站项目的提示词

```text
请在 D:\FH6\nina-developer-site 接手「Horizon Link 问题反馈」。先读网站项目自身的 AGENTS.md 和 docs/HANDOFF.md，核对 Git 和现有管理台、登录授权、数据库迁移与数据目录。目标是接收 Android/iOS App 发出的反馈，并让我登录网站管理台查看和处理。沿用当前 React/Vite、Express/TypeScript、SQLite 和站点样式。

1. 在正式域名 ninaaa.cloud 增加 POST /api/horizon-link/feedback。原生 App 直接提交 UTF-8 application/json，无网站登录、Cookie 或内置密钥。只接受 requestId、message、platform 和可选 appVersion。requestId 必须为 32 位小写十六进制；message 去首尾空白后为 1–2,000 个 Unicode 码点，允许换行；platform 仅 android 或 ios；appVersion 格式为 ^\d{1,9}\.\d{1,9}\.\d{1,9}\+\d{1,10}$，例如 0.3.2+5。拒绝未知字段和无效 UTF-8；请求体按 16 KiB 限制。

2. 用网站现有 DATA_DIR 下的 SQLite 做增量迁移。在事务或唯一约束下按 requestId 去重。首次成功写入后返回 HTTP 201 + application/json 的 {"id":"<原 requestId>"}；相同编号和相同内容重试返回 HTTP 200 和同一回执；编号相同但内容不同返回 409。无效字段返回 400，超大请求返回 413，非 JSON 返回 415，限流返回 429。接口不重定向，也不公开提供任何反馈的读取能力。

3. 复用网站的可信代理设置及现有基础设施做限流，限制单来源和全局写入频率。反馈表只保存协议字段、服务端接收时间和处理状态。不要把完整 IP、反馈正文、凭据或 Cookie 记录到应用日志或分析统计；不要采集设备标识、遥测、设置或附件。正文作为纯文本显示。反馈数据最长保留 90 天，落实自动清理并核对备份保留；管理员可按编号删除反馈以响应隐私请求。

4. 在现有管理台加「Horizon Link 问题反馈」。提供分页列表、待处理/已处理筛选、详情、标记已处理和确认删除。详情显示编号、接收时间、平台、版本、问题全文。所有查询和修改复用服务端管理员授权及站点现有写请求保护；匿名、普通用户、已禁用管理员均无权访问。反馈页面和数据响应使用 no-store。

5. 先用隔离数据库测试合法提交、同编号并发重试只保存一条、冲突编号、限流、超长/非 JSON、匿名及普通用户拒绝、管理员查看/处理/删除、90 天清理、换行和 HTML 文本显示。运行 npm test、npm run check、npm run build，并按网站约定验收管理页。保留已有数据、入口和发布配置。把结果写到网站项目自己的交接与测试文档；按网站现有部署授权流程上线，不改 App 仓库或 COS。

上线后将可用的 HTTPS 路径和联调结果告知我。用一条明确标注的测试反馈核对 App 成功回执与后台详情，反查编号一致后删除测试反馈。
```

## 联调及 Android 发布条件

- 用测试反馈核对网站成功回执、后台可见及删除。App 应核对同编号重试、断网、错误回执和恢复后发送。只有有效服务器回执才显示成功。
- 双语政策新增反馈字段、接收方、授权管理员访问及 90 天留存。发布前验证网站落实该留存规则，并让在线政策、包内告知和公开构建资料的生效日期一致。新版会再次请求隐私同意。
- Android 候选版本为 `0.3.2+5`。验过线上功能后，用原备案签名构建，经英文路径暂存并核对签名和 SHA-256。发布时走 [GitHub 发布流程](GITHUB_RELEASE.md) 的 App 源码导出边界。仅在 Android 下载可用后按单独授权更新 COS Android 版本项。
